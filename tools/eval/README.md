# Eval set (PRD section 9)

`utterances.jsonl` holds 400 labelled captures: 160 Hinglish, 140 Hindi (Devanagari),
100 English. It is generated by `gen_eval.py` (fixed seed) from hand-written phrasings
and slot values, plus hand-written multi-item, vague, update and question cases.

```bash
python tools/eval/gen_eval.py
```

The first line is metadata (`ref_time`, the moment relative dates resolve against:
Wednesday 7 October 2026, 09:30 IST). Every other line:

| Field | Meaning |
|---|---|
| `id`, `lang`, `category`, `text` | `lang` is `hinglish`, `hindi` or `english` |
| `intent` | capture, update, query, contact_log, remember, chat, other |
| `domain`, `kind` | life area and sub-kind (see docs/spec/data.md), or null |
| `tool` | add_item, update_item, find_items, add_person, log_contact, remember, log_metric, none |
| `needs_llm` | true when only System 2 can handle it (multi-item, vague, chat) |
| `urgency` | low, medium, high (due today or overdue = high, within 2 days = medium) |
| `entities` | due/start (local `YYYY-MM-DD[THH:mm]`), amount_paise, person (canonical Latin name), direction, status, channel, cadence_days, metric/value |
| `split` | train (70%) or test (30%), stratified by category and language. Never train on test |

`log_metric` is one tool beyond the PRD's S1-1 list: health readings can be filed
without the model.

## Recordings

Audio for the speech benchmarks (VO-3) is recorded on the CMF Phone with the in-app
recorder (added in P2), in a quiet room and a noisy room. Recordings stay on the PC in
`tools/eval/audio/` (not committed).
